# procmat core: decisions (core agent, 2026-10-30)

Decisions taken for the shared core without the user, with the reason. They follow tools/materials/DECISIONS.md
(D1-D11); the docs agent merges them there. Evidence classes: these are all class C (our implementation) unless a
measurement is quoted.

| # | decision | reason |
|---|---|---|
| C1 | Package `procmat` = `core` (builder, contract groups / materials, coordinates), `rig`, `bake`, `graphdump`, `road_adapter`, `imaging`, registry in `__init__`, self-test materials in `demo` (key `coredemo`, `LIBRARY = False`); CLI `tools/materials/run.py`; tests `tools/materials/tests/test_core.py`. Nothing imports the road tool: `road_adapter` re-implements the 15-line modifier input setter of `tools/roads/mrs/nodes.py mod_input_set` (Blender 5.2 `mod.properties.inputs.<identifier>.value`, IDProperty fallback). | D1 (separate from the road tool) while staying compatible with it |
| C2 | `Coordinates` reproduces the road tool's `_G` exactly: object mode = Object coordinates (metres), W = 0; UV mode = `UVMap` attribute x Tile Size, 4D point (R cos u, R sin u, R cos v) rotated about (0.53, 0.71, 0.46) by 0.83 rad, W = R sin v, R = Tile Size / 2 pi; the group's scale input multiplies V and W. Built lazily in a frame "Coordinates". | a flat torus has arc length = metres, so 4D textures keep their size and repeat every Tile Size; identical behaviour to MRS materials (D2) |
| C3 | `noise4` / `voronoi4` sample 4D in both modes by default; `exact3d=True` adds a 3D texture for object mode mixed by Use UV. | 4D in both modes keeps the Blender preview and the baked tile statistically identical. Measured: a 2D slice of 4D Voronoi cells varies more in cell size and Distance-to-Edge width than 3D cells (render `tmp/materials_core/renders/CoreDemo_4Dslice_vs_exact3d.png`), so materials whose look depends on clean cells (cobblestone joints) can keep the tutorials' 3D cells in object mode |
| C4 | Textures without a 4D variant: `seamless(make, blend)` (4-sample smoothstep cross-fade of f(P), f(P-(T,0)), f(P-(0,T)), f(P-(T,T)) with P = fract(UV) x T) as the generic fallback; `periodic(size)` / `wrap()` (road-tool method) for analytic patterns; `snap_scale(scale, period)` for periodic textures (Wave bands 2 pi / 20, Checker 2). A periodic 2D Voronoi built from math nodes was not made (possible later, for UV-mode stones with even joints). | D5; exact repeat proven (below); the cross-fade costs 4 evaluations and lowers contrast slightly in the blend band, which is acceptable for a fallback |
| C5 | `contract_material`: one group node named `MRS`, label = group name, BSDF -> Surface; displacement is off by default (`displacement_method = BUMP`), `displacement=True` links `Displacement` (or `Height` via a Displacement node, midlevel 0, scale 1) and sets BOTH; materials get a fake user and `mat["procmat"]`; viewport colour / roughness / metallic are set. | road meshes are coarse (true displacement would tear them); fake users keep materials in saved libraries; the road tool's glTF export falls back to the viewport values for non-MRS materials (`export.engine_material`) |
| C6 | `Use UV` / `Tile Size` are appended to every contract group in a closed panel "Mapping" (names unchanged). | the road tool and `bake` look them up by name; panels only change the UI |
| C7 | `bake` uses its own scene `PM_Bake` through a context override (verified headless; falls back to the context scene), a bake plane with two UV maps (`UVMap` read by the material, `PM_BakeUV` the 0..1 raster), displacement as bump during the bake, 8-bit PNG, images removed after saving, inputs restored. | a road library scene (600 MB base.blend) must not be synced for a 4 m plane; the second UV map makes shifted-UV bakes (periodicity test) possible without texels falling off the image |
| C8 | Seam evidence: `seam_metric` reports ratio vs the mean neighbour step, outlier vs the worst interior column / row and a percentile; the decisive test is `periodicity()` (a bake with the material's UVs + (0.5, 0.25) must equal the tile rolled by (256, 128) px). | one seam column is a small, pattern-dependent sample (a snapped joint line on the seam inflates `ratio` while the tile is exact). Measured: PM_CoreDemo rolled MAD 0.00076, corr 0.9999 (control without repeat 0.10 / 0.44); object-mode control seam outlier 8.3 / 9.3 vs 0.85 / 0.47 in UV mode |
| C9 | Rig: its own scene `PM_Rig` (collection `PM_Rig_Objects`); EEVEE (`BLENDER_EEVEE` read from the enum) for previews, Cycles GPU (OPTIX first, CPU fallback) for bakes; worlds from bundled HDRIs only; AgX view transform; tutorial lights optional (two area lights approximating the tutorials' emission planes of strength 100 / 5); objects use `matrix_basis` for framing (a new object's `matrix_world` is stale headless). | D6, D9; fast previews; reproducible lighting |
| C10 | `side_by_side` uses Pillow; Blender 5.2 bundles no Pillow, so `imaging.py` re-runs itself in the system Python (`python -I`, Store alias skipped); numpy-only join without labels as the last fallback. | the brief asks for Pillow; no OpenCV |
| C11 | `road_adapter.assign` sets the modifier input by interface name and, for Asphalt / Paving Material, the overriding menu (Asphalt Condition / Sidewalk Surface) to "Default" (also in the object's remembered `mrs_inputs`); it records `obj["pm_materials"]`; `reapply()` restores them after the road tool's `set_road()` / `refresh_all()`, which re-apply MRS_* materials. | proven in base.blend: with Condition = Worn the socket is ignored (evaluated mesh: MRS_AsphaltWorn), after `assign` the evaluated road carries PM_CoreDemo on 240 faces; `set_road()` resets, `reapply()` restores |
| C12 | Bus shelter glass = `MRS_F_BusShelter` and `MRS_F_BusShelter_LOD1` slot 1 `MRS_FurnitureGlass` (slot 0 `MRS_FurnitureAtlas`); older placeholders `MRS_BusShelter` / `MRS_BusStopShelter` slot 1 `MRS_PropGlass`. `replace_slot_materials(per_object=True)` leaves the shared library mesh untouched. | read in `tools/roads/mrs/furniture.py` (`_finish_mesh`: material_index 1 = glass) and confirmed in base.blend |
| C13 | Tests run in two Blender runs started one after the other by a system-Python launcher; base.blend is opened read-only and never saved; outputs in `tmp/materials_core/`. | one Blender at a time; nothing applied to the game (D10) |
| C14 | Material modules register themselves (`register(sys.modules[__name__])`, key = `KEY`); `discover()` imports asphalt / cobblestone / glass plus any other module in the package, skips a missing one with a message and prints the traceback of one that fails. | other agents add modules in parallel; a broken module must be loud, a missing one harmless |
| C15 | Group trees are laid out automatically (columns by distance to the output, one band per top-level frame, no overlaps - checked by the tests; one Group Input per frame with unused sockets hidden). | the user edits these trees in Blender |
| C16 | `graphdump` marks settings / values as non-default against a freshly created node of the same type; builders can tag nodes with `note=` (custom property `pm_note`) for evidence classes. | NODES.md documents need exact, reproducible tables |
