# PM_Cobblestone: decisions taken while building (class C) and the version-adaptation table

Build step of the cobblestone material (`tools/materials/procmat/cobblestone.py`) from the segment specifications
`GRAPH_SPEC_a.md` / `GRAPH_SPEC_b.md` (video `30vbbpy9zwg`, Ryan King Art, Blender 5.0.1). The library decisions
D1-D11 (`tools/materials/DECISIONS.md`) apply; the extraction decisions are in `DECISIONS_a.md` (a1-a9) and
`DECISIONS_b.md` (b1-b10). CB1-CB15 are summarised in `tools/materials/DECISIONS.md`; CB16 (audit) was appended there as well.

Evidence classes: A frame, B narration, C our implementation / inference, D unresolved.

## Decisions

| # | decision | reason |
|---|---|---|
| CB1 | ONE node group `PM_Cobblestone` (the tutorial's group "Cobblestone Ground") used by TWO materials: `PM_Cobblestone` (displacement_method BUMP; the group's Displacement output still feeds Material Output > Displacement, so the stone relief becomes bump) and `PM_CobblestoneDisplaced` (method BOTH = the video's "Displacement and Bump", A 25:42 / 26:51). | The node graph is identical; only the material setting differs. The road tool's meshes are coarse (0.5 m and more): true displacement there would move a few vertices by up to 6 mm at random, so the road material keeps bump (contract rule in API.md). Dense preview meshes use the displaced one. One group = one set of controls to maintain. |
| CB2 | Every texture is built with `exact3d=True`: object mode samples the video's 3D Noise / Voronoi at the video's coordinates; UV mode (Use UV = 1) samples the 4D torus. | Object mode then reproduces the video's exact field. Verified: a camera-direction search found the video's stones on our sphere (VALIDATION.md, the same stone layout). Cost: 9 textures evaluated twice (18 texture nodes). |
| CB3 | Ramp positions and the mask grey use segment a's typed field values (cell ramp 0.000 #999999 -> 0.035 black, dirt colour 0.151 / 0.553, dirt moss 0.467, sharp moss 0.324, rock moss mask 0.407 / 0.651, final 0.030) instead of segment b's bar measurements (0.02 / #989898, 0.155, 0.469, 0.314, 0.645). | a2: a typed value beats a pixel measurement. Checked visually: with 0.035 the stone fill of the tutorial build at 26:08 is matched (comparisons/t2608_vs_ours_aligned.png); 0.02 would make the stones smaller. |
| CB4 | Coordinates: the video's Texture Coordinate (Object) -> Mapping (Point, location 0, rotation 0, Scale <- Material Scale) is the core `Coordinates` with scale = Material Scale / Pattern Size. A Point mapping with zero location / rotation is a multiplication, so object mode is the same vector. | Contract (D2): one coordinate block that also serves the seamless UV mode. |
| CB5 | Scale conversion: none needed. The video's object is an icosphere of radius 1 m scaled by 0.5 with the scale applied (B 4:45-4:53, A typed 0.5 at 4:50): Object coordinates are metres. `Pattern Size` (m, default 1.0, C) is added as the metre control: V = Object x Material Scale / Pattern Size. Stones are 1 / Cobblestone Scale = 1/7 m = 0.14 m at the defaults. | D4. Real cobbles / setts are 0.1-0.2 m, so the defaults are already street scale (renders/PM_Cobblestone_road.png). |
| CB6 | Displacement Strength and the bump Distances stay in object-space metres and are not divided by Pattern Size. | They are the video's controls (A); with Pattern Size 2 the stones double in plan but keep 6 mm relief; raise Displacement Strength by hand when wanted. |
| CB7 | The group interface is the tutorial's 36 inputs (segment b, b1): same names, panel membership and order, defaults, min / max and Float / Factor subtypes. `Pattern Size` follows `Material Scale` (outside panels); the contract inputs `Use UV` / `Tile Size` follow in the closed panel "Mapping". Tooltip texts are ours (the video's are truncated, U9). Material Scale min / max -inf / inf are stored as +-3.4e38. | The product file's 34-control variant (0:09-0:11) is not the tutorial's result (b1). |
| CB8 | Outputs (C): `BSDF` (the tutorial's "Shader"), `Albedo` = the same two mixes applied to the Base Colors (rock colour mix / Rock Moss Color by the moss mask, then dirt / rock by the final ramp), `Displacement` (the tutorial's output, A), `Height` = cell ramp grey x Displacement Strength (stone relief in metres, 0 in the joints, 6.4 mm on the stones). | The contract needs Albedo for bakes; Height is for a later height-map export. |
| CB9 | Hidden Principled BSDF settings (distribution, subsurface method, dropdowns) stay Blender 5.2's defaults; the dirt BSDF's Metallic / IOR / Alpha = 0 / 1.5 / 1 (b7). Bump Filter Width 0.1 set explicitly (A). | Not visible in the video (U6, U15 of segment a). |
| CB10 | Reroutes are left out; one Group Input per frame (the core's habit) stands for the video's 8 per-frame Group Input copies. | Functionally transparent (b3). |
| CB11 | UV mode: the Linear Light warp moves V only; W (the 4th torus coordinate) is not warped. | The warp colour comes from a 4D noise on the torus, so the warped coordinates are still periodic; warping W too is not in the video and not needed. |
| CB12 | Validation scene (scripts/render_tutorial.py): icosphere subdivisions 4 + Subdivision Surface render level 3 (the build file's 642-vertex sphere, A, with the narrated modifier, B) = 81,920 faces, radius 0.5 m; Cycles GPU, Film Transparent, Blackman-Harris 1.5 px, Filmic + Very High Contrast; camera 80 mm from -Y, level (azimuth 0, elevation -1 deg, roll 0: found by the view search, C); sun 15 / 6000 K / 0.526 deg from azimuth -45 deg, elevation 45 deg (C: closest of 8 tried directions); disk rim light 1 m 300 W #FFEDE0 at (0.6, 2.2, 0.8) m (C); world = bundled `courtyard` HDRI strength 1 (D6, closest of city / courtyard / forest / sunset). | The video does not show light or camera transforms (D, U-items of segment a). |
| CB13 | The product render (0:04, identical to the closing render at 40:16) is not the reference for the stone fill: its stones are fuller with narrower joints than both the tutorial build at 26:08 and our build. Our defaults stay the tutorial's; `Cobblestone Individual Size` about 0.5 approximates the product look (comparisons/t0004_stone_fill_individual_size_0p6_0p4_0p8.png). | The product file's internals are never shown (b1); the tutorial build at 26:08 matches our 0.6 (comparisons/t2608_vs_ours_individual_size_0p6_0p5.png). |
| CB14 | `.gdignore` added at `tools/materials/reconstruction/cobblestone/` (covers evidence/a, evidence/b, renders, comparisons). The `*.png.import` side files the open Godot editor had already written under `evidence/b/` were left in place (removal left to the docs step / the user). | Same reason as a9: evidence is not game content. |
| CB15 | Viewport colour / roughness of both materials (also the road tool's glTF fallback for non-MRS materials) = the linear means of the 4 m UV-mode bake: (0.0200, 0.0200, 0.0139) and 0.72 (re-measured after CB16; first build (0.0187, 0.0183, 0.0122) and 0.74). | Measured, VALIDATION.md section 4. |
| CB16 | Audit CB-1 / CB-2 (UV mode only, object mode unchanged): the 4D Smooth F1 twin of the cell mask gets Smoothness = Cobblestone Individual Size x 0.82 (`uv_smooth_gain`), and the 4D rock Voronoi Distance feeding the rock bump is multiplied by 1.41 (`uv_rock_gain`). A mode adaptation, not a video value. | A 2D slice of 4D cells has more neighbours at similar distances: at the video's smoothness the baked tile covered 36 % stone vs 49 % in object mode (median stone 8.9 vs 10.2 cm), and the 4D rock Voronoi std was 0.71x. Calibrated by a sweep at the defaults on a 4 m tile (gain 1.0 / 0.8 / 0.7 -> 36 / 50 / 58 %); after: 48.6 % vs 48.9 %, area-weighted median 12.6 cm both, stone-top normal std 0.0579 vs 0.0564. Smoothness scaling keeps the edge sharpness (a distance gain was tried first: 0.6 only reached 45 % and softens the edges). VALIDATION.md section 6. |

## Version adaptation (Blender 5.0.1 in the video -> Blender 5.2.3 LTS)

| tutorial node / behaviour | Blender 5.2 equivalent | adaptation | expected effect |
|---|---|---|---|
| Texture Coordinate Object -> Mapping (Point, Scale <- Material Scale) | core `Coordinates` (Object x scale; UV mode: 4D torus of UVMap x Tile Size) | Mapping node replaced by a multiply with Material Scale / Pattern Size (CB4) | none in object mode; UV mode is seamless |
| Noise Texture 3D fBM (x6: distortion, dirt, dirt moss, rock, rock moss mask, rock moss) | same node, 3D twin + 4D twin mixed by Use UV | object mode = the 3D node; UV mode = 4D on the torus | object mode identical (same stones found); UV mode: same statistics, different field |
| Voronoi Texture 3D Smooth F1 / F1 (cell mask), Smooth F1 with Detail (rock) | same node, 3D twin + 4D twin | as above (fractal Detail works in 4D too); UV mode: 4D smoothness x 0.82, 4D rock distance x 1.41 (CB16) | UV mode: same stone coverage / size statistics as object mode; cells slightly more polygonal, size spread a little wider |
| Mix (RGBA) Linear Light, Factor 0.2: vector distortion | ShaderNodeMix RGBA LINEAR_LIGHT (same node) | W not warped in UV mode (CB11) | none in object mode |
| Mix (RGBA) Difference / Mix, ColorRamp, Hue/Saturation/Value, Mix Shader | same nodes | none | identical |
| Bump (Strength, Distance, Filter Width 0.1 shown in 5.0.1) | same node, same inputs | none (unlike the 3.2 asphalt video, 5.0 already had Filter Width) | identical |
| Displacement node (Object Space, Midlevel 0, Scale 0.02) + material "Displacement and Bump" | same node; `displacement_method = 'BOTH'` | PM_CobblestoneDisplaced keeps BOTH; PM_Cobblestone uses BUMP (CB1) | road material: relief as bump only, silhouettes flat |
| Principled BSDF (5.0 sockets) | same sockets (Base Color, Metallic, Roughness, IOR, Alpha, Normal) | hidden dropdowns at 5.2 defaults (CB9) | none expected |
| Cycles material "Bump Map Correction" on (A 26:51) | Cycles material setting, default on in 5.2 | not set explicitly | none |
| Color management Filmic + Very High Contrast | still available in 5.2 (view "Filmic", look "Very High Contrast"; the look enum is dynamic, set by name) | used in the validation renders only | identical tone mapping |
| Sun temperature 6000 K | `Light.use_temperature` / `Light.temperature` (5.2) | used | identical colour |
| fish_hoek_beach_1k.hdr (Poly Haven) | bundled `courtyard.exr` (D6) | lighting difference, reported separately | different sky light and reflections |

## Scale conversion

Video object space = metres (radius 0.5 m icosphere with scale applied). Conversion factor 1: every Scale value is the
video's; `Pattern Size` = 1 m reproduces the video. Feature sizes at the defaults: stones 1/7 m = 0.14 m; dirt noise
1/20 m; dirt moss 1/25 m; rock moss patches 1/15 m; rock Voronoi bump cells 1/12 m; distortion 1/2 m.
UV mode: the torus arc length is metres, so a 4 m `Tile Size` keeps these sizes and repeats every 4 m.
