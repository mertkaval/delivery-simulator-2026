# Asphalt material (PM_Asphalt): build decisions

Decisions made without the user while building the asphalt material from the reverse-engineered spec
(`GRAPH_SPEC_all.md`; the extraction's own decisions are in `DECISIONS_all.md`). They follow the binding library
decisions D1-D11 (`tools/materials/DECISIONS.md`), into which the docs agent merges them. Evidence classes: **A**
observed in a frame, **B** narration / recipe repo, **C** our inference or implementation, **D** unresolved.
Everything here is class C unless a measurement is quoted.

## Decisions

| # | decision | reason / evidence |
|---|---|---|
| AS1 | Two materials from one builder (`procmat/asphalt.py`, key `asphalt`): **PM_Asphalt**, the library material, where the six ColorRamps whose stops or colours are controls become a clamped linear Map Range (black/white stops) or a Mix between two colour inputs (the colour ramp); and **PM_AsphaltTutorial**, the video's graph with its literal ColorRamp nodes and constants and no controls except the contract inputs and Pattern Size. | The video creates no group and exposes no controls; a ColorRamp stop cannot be driven by a socket. A 2-stop linear ramp is exactly `clamp((x - lo) / (hi - lo))`, so the maths is unchanged. The literal twin keeps the reconstruction auditable. Measured: albedo of the two differs by at most 4/255 (mean 0.004/255; Cycles evaluates a ColorRamp through a 256-entry table, Map Range exactly). |
| AS2 | Textures that are 3D in the video (six Noise nodes and the Smooth F1 base Voronoi) are built with `exact3d=True`: object mode samples the same 3D texture at the same coordinates as the video, UV mode samples a 4D twin on the core's seamless torus, mixed by Use UV. The cracks Voronoi stays a single 3D node in both modes. The pebble Voronoi is 4D in the video (W = 0); object mode keeps W = 0, UV mode uses the torus W. | Object mode should be the video's material, not a 4D look-alike (the core notes that 2D slices of 4D Voronoi cells vary more). The cracks Voronoi samples the cracks noise *colour*, which is periodic on the torus in UV mode, so a 3D Voronoi of it is seamless. Cost: EEVEE evaluates both twins of each texture. |
| AS3 | Metres: the video's Object coordinates on its 1 m-radius sphere are taken as metres (U7, radius assumed). **Pattern Size** (m, default 1) divides every texture coordinate (V and W): 1 = the video's sizes. **Aggregate Size** (m, default 1/110 = 9.1 mm) sets the pebble Voronoi Scale = Pattern Size / Aggregate Size and the grain bump noise Scale = 60/110 of that, so the micro texture stays at a physical size when the macro pattern is scaled. | D4 (a size in metres). Pebbles of 9 mm are a realistic asphalt aggregate. Checked: a 2 m bake at Pattern Size 1 and a 4 m bake at Pattern Size 2 (aggregate doubled too) are bit-identical (MAD 0.0, corr 1.0); keeping the aggregate at 1/110 m changes only 0.4 % of the pixels, all pebbles (`checks/metres_check.json`). |
| AS4 | Controls of PM_Asphalt (defaults = the video's values): Crack Amount 0.499, Crack Width 0.094, Damage Amount 0.35 (white stop follows at +0.092), Damage Darkness 0.338, Roughness Min 0.4072 (#ABABAB), Color Dark #1A1817, Color Light #4D4D4D, Bump Grain / Cells / Cracks / Damage 0.1 / 0.2 / 0.3 / 0.4, Bump Filter Width 1.0, Pattern Size 1 m, Aggregate Size 1/110 m; panels Colour, Cracks, Damage, Surface and the contract's closed panel Mapping (Use UV, Tile Size 4 m). | The spec's suggested interface (class C, values A), plus D2 / D4. Names are distinct from every input name the road tool's presets set (`Cracks`, `Patch Amount`, `Wetness` ...), so `apply_material_preset()` never changes them (checked in `checks/road_check.json`). |
| AS5 | The four Bump nodes use **Filter Width 1.0**, not the 5.2 default 0.1. Exposed as `Bump Filter Width` in PM_Asphalt (a constant in the literal twin). | U13 asked to compare. Same view, same pixel scale as the video (1301 px square): mid-band relief contrast (std of band-passed log luminance, 1.5-6 px) in three windows: video 0.279 / 0.339 / 0.338, FW 1.0 0.256 / 0.347 / 0.323, FW 0.1 0.161 / 0.251 / 0.225, FW 2.0 0.319 / 0.410 / 0.377 (`comparisons/metrics.json`, `cmp_zoom_bump_filter_width.jpg`). Denoising on / off changed nothing measurable. |
| AS6 | Damage mask black stop 0.35. | Spec choice (U1: 0.343 last legible before a jump cut, 0.350 measured after). Measured after the audit (ASP-2, object-mode bake 16 m, 64 windows of 2 m): 0.343 gives a damage fraction of 0.0655 against 0.0792 at 0.35 (-17 %), so the other reading would make the damage *smaller*, not larger like the video's view (`checks/damage_views.json`). 0.35 kept. |
| AS7 | Validation scene: the core rig (`rig.scene`, `rig.world`, `rig.render`, `rig.preview` for the road) plus local additions in `scripts/video_scene.py`: the video's icosphere (subdivisions 6 = 10,242 v as the 3.2 status bar, radius 1 m), Cycles GPU 256 samples + denoise, Filmic (U3), square 1301 px (the video's displayed Render Result size), 50 mm camera framing the sphere at 95 % of the height (U5), emission planes as in the video (key disc Strength 100 with a subdivided quad, rim strip Strength 5; the rig's `tutorial_lights()` are area lights on the other side), black background. Key direction (0.80, 0.58, 0.25) in camera space and disc size 2.1 at 4 m, rim behind on the left: fitted to the reference's brightness in 24 sectors (log-rms 0.22). | U5 / U6 are hidden; fitting the light to the reference separates lighting from material differences. The rig is not modified (core files are read-only for this agent). |
| AS8 | World: bundled `studio.exr`, strength 0.2, **desaturated** (Hue/Saturation 0 in the world, script option `--tinted-world` to keep its colour). Tried: `studio` tinted (blue fill), `interior` 0.15-0.2 rotated 0 / 180 (warm fill like the video, but a blue window reflection across the left half and a sun spot), `courtyard` 0.2 / 0.3 (red fill). | D6 (no download of machine_shop_02). Chroma in the shadowed window: video (1.052, 1.020, 0.928) = warm fill; ours (1.009, 1.000, 0.991) = neutral; albedo (1.019, 0.997, 0.984). The tint difference is the HDRI's, reported as lighting. |
| AS9 | The camera of the comparisons looks from -Y (direction (0, -1, 0)), not from the video's direction. | A full view search (below, AS10) found no view of our sphere that reproduces the video's patches, so no view is "the same"; comparisons are statistical (same scene, framing, scale and lighting). |
| AS10 | View search as evidence: an equirectangular albedo map of our sphere (`scripts/sphere_maps.py`) was matched against the 26:38 render over 6,000 directions x 60 rolls at a 50 mm perspective, then refined (direction +-4 deg, roll +-6 deg, 8 distances incl. orthographic). Best correlation 0.21-0.28 against random views 0.00 +- 0.05; the same search on our own render from a known camera recovered it within ~1 deg (corr 0.63). Recorded as unresolved (D): either Blender 5.2's Noise / Voronoi values differ from 3.2's, or the video's sphere is not a 1 m sphere in object space. | Object mode with AS2 would have reproduced the video's exact cracks and patches if both held; the control proves the search works. |
| AS11 | Principled: GGX (5.2 default MULTI_GGX), IOR 1.5, Specular IOR Level 0.5 (F0 0.04 like 3.2's Specular 0.5), Subsurface / Coat / Sheen / Transmission weights 0, Random Walk; Subsurface radius / colour left at 5.2 defaults (U10, no effect at weight 0). | U14. |
| AS12 | MixRGB -> `ShaderNodeMix` RGBA with `clamp_result = False` and `clamp_factor = True` (MixRGB clamped its factor); use_alpha has no 5.2 equivalent and was off (U11). | Same formulas: Linear Light A + f (2B - 1), Darken / Lighten min / max at factor 1, Mix lerp. |
| AS13 | Reroutes `rr_color`, `rr_cracks`, `rr_damage`, `rr_bump` and the frames Color / Cracks / Damage are kept; the other video nodes stay outside frames; the contract's coordinate plumbing lives in the core's own frame "Coordinates". Layout by the core (`G.finish()`). | Graph mirrors the video (spec A5); reroutes are free at render time. |
| AS14 | Viewport colour (0.0278, 0.0271, 0.0267) and roughness 0.59: the means of the 4 m UV-mode bake at the defaults (re-measured after AS17; before it 0.0264 / 0.0257 / 0.0253 and 0.58). | The road tool's glTF export writes a flat Principled from these values for non-MRS materials (core note); they should be the material's average. |
| AS15 | Evidence: renders as PNG in `renders/` (metrics are computed from them), comparison panels as JPEG quality 90 in `comparisons/` (viewing only; 15 MB of PNG became 4 MB), numbers in `comparisons/metrics.json` and `checks/*.json`. Scratch renders, round renders, maps and logs stay in `tmp/materials_asphalt/`, bakes in `tmp/materials_bake/asphalt/` (not for commit). | D7 spirit: keep cited evidence small and reproducible; every panel is regenerated by `scripts/compare.py`. |
| AS16 | Road-tool compatibility is proven in `tmp/roads/city/base.blend` opened with `--factory-startup` (no user add-ons) and never saved: append from a saved procmat library, assign to `Asphalt Material`, preset isolation, `set_road()` + `reapply()`, and the road tool's own `bake_tiles()` on an in-memory copy named `MRS_PMAsphaltCheck` (it only looks up `MRS_<suffix>` names). | D10 (nothing applied to the game); the user's "make sure you can use materials in road tool". Nothing under `tools/roads/` was written (bytecode off). |
| AS17 | **UV-mode distribution match** (audit ASP-1): in UV mode the output of each 4D twin is remapped linearly, `gain x 4D + offset`, before the `object 3D \| UV 4D` Mix (seven Multiply Add nodes `<id>_uvmatch_<output>`, constants `UV_MATCH` in `procmat/asphalt.py`; per channel for the two noise Colours; the float ones clamped to 0..1). Object mode is unchanged (it never reads them). Applied to both materials (a mode adaptation, not a video value). | The audit measured UV mode flatter than object mode. Per texture (`scripts/uv_match.py`: 1-spp emission bakes = point samples, 32 m plane, 2048 px, both modes): Blender 5.2's 4D Noise has 1.5-2.4 % less spread in Fac and 2-13 % less per colour channel (the 3D colour channels differ from each other: std 0.062 / 0.068 / 0.065, the 4D ones are equal), and the 4D Smooth F1 Minkowski-32 Voronoi Distance is much narrower and lower (std 0.075 vs 0.104, mean 0.285 vs 0.310). gain = std3 / std4, offset = mean3 - gain x mean4; the linear fit leaves quantile errors <= 0.003 from p5 to p95 (Voronoi p1: 0.014). The distributions are scale-free, so the constants hold for every Pattern Size, Aggregate Size and Tile Size. After: every output matches (std ratio 0.998-1.000); whole-material numbers in VALIDATION.md section 7a. |
| AS18 | **Damage amount kept at the video's values** (audit ASP-2). | Measured, not assumed: across 24 views of our sphere (same scene, lights following the camera) the true damage coverage of the scored lit region (from a rendered `damage_mask_ramp` mask) is 0.030 mean, sd 0.0135, range 0.011-0.070; our comparison view (view 0) has 0.022, below the mean. One detector (fine-band / mid-band texture energy + local darkness, threshold calibrated on our views; per-view fraction corr 0.74 with the truth, mean abs. error 0.0075) gives the video's 26:38 render 0.041, z = +0.8 against our views' detected spread, with 4 / 24 views above it. A one-view difference of this size is within the view-to-view spread on a 1 m sphere (the scored region is ~0.8 m^2 of a curved field, not the 2 m x 2 m flat windows of the audit's estimate). The 0.343 stop reduces damage (AS6). The 3.2 Noise Fac histogram cannot be measured (3.2 not installed, no downloads; D). The video's detected patches are not darker than ours (median smoothed luminance 0.187 vs 0.159, lighting not separable). No change to Damage Amount; `checks/damage_views.json`, `comparisons/cmp_damage_views.jpg`. |

## Version adaptation: Blender 3.2 (video) -> 5.2.3 (build)

| tutorial node / behaviour (3.2) | Blender 5.2 equivalent | adaptation | expected effect |
|---|---|---|---|
| MixRGB Linear Light / Mix / Lighten / Darken, Clamp off | `ShaderNodeMix`, data_type RGBA, same blend_type | Color1 -> A, Color2 -> B, Fac -> Factor; clamp_result off, clamp_factor on | none (same formulas, factor clamped as before) |
| ColorRamp (`Fac` input) | `ShaderNodeValToRGB` (literal twin); Map Range / Mix (PM_Asphalt) | input looked up by identifier `Fac` (named Factor in 5.x); hex stops converted sRGB -> linear | none; Map Range exact vs the ramp's 256-entry table: albedo difference <= 4/255 |
| Noise Texture 3D, fBm (no Normalize / Lacunarity inputs in 3.2) | Noise Texture, noise_type FBM, Normalize on, Lacunarity 2 | defaults (4.0 added these inputs with 3.2-equivalent defaults) | the same formula; identical values not confirmed (AS10, D) |
| Voronoi single octave | Voronoi, Detail 0, Normalize off | defaults | the same; identical values not confirmed (AS10, D) |
| Bump Distance 1.0 (3.2 default) | Bump created with Distance 0.001 | set 1.0 | without it the relief disappears |
| Bump without Filter Width | Bump Filter Width (default 0.1) | 1.0 (AS5) | the 3.2 relief contrast; 0.1 gives about half |
| Principled v1: GGX, Specular 0.5, IOR 1.45 (transmission only), Disney diffuse, additive layering | Principled v2: distribution GGX, IOR 1.5, Specular IOR Level 0.5 | same F0 0.04; other weights 0 | v2 conserves energy between specular and diffuse and has no retro-reflective diffuse: slightly darker at grazing angles; not separable from the lighting differences here |
| Texture Coordinate > Object into every texture | the same node inside `procmat.core.Coordinates`; V = Object / Pattern Size | Pattern Size 1 = the video | none in object mode |
| 3D textures | 3D in object mode + 4D twins on the torus in UV mode (AS2), the 4D outputs remapped to the 3D distributions (AS17) | Use UV = 1 for bakes | seamless tiles; UV mode is a different field with the object-mode statistics: measured, VALIDATION.md 7a (without AS17 the 4D twins are narrower: base-cell mottling 26 % flatter) |
| Voronoi 4D, W 0 | the same; W = torus W in UV mode | - | none in object mode |
| Filmic view (3.2 default, U3) | Filmic still exists in 5.2 (the library's previews default to AgX) | validation renders use Filmic, look None | - |
| Cycles GPU, unknown samples / denoiser (U2) | Cycles GPU (OptiX), 256 samples, OIDN | denoise on / off compared: no measurable change of the relief | - |
| HDRI machine_shop_02_1k (Poly Haven, U12) | bundled `studio.exr`, desaturated, strength 0.2 (AS8) | D6 | warm fill in the video, neutral here (lighting) |
| Emission planes Strength 100 / 5 (U6 sizes, positions) | emission planes Strength 100 / 5, sizes / directions fitted (AS7) | - | lighting only |

## Scale conversion (video object space on a 1 m-radius sphere = metres, U7)

| texture | video Scale | feature size at Pattern Size 1 | follows |
|---|---|---|---|
| colour noise (warps the base cells by +-0.1 m) | 18 | ~5.6 cm | Pattern Size |
| base cells (Smooth F1, Minkowski 32) | 10 | 0.10 m cells | Pattern Size |
| crack warp noise (its colour is the cracks Voronoi's Vector) | 2.5 | ~0.40 m; crack cells follow its colour gradients | Pattern Size |
| crack mask noise | 4.5 | ~0.22 m (about half the surface keeps cracks) | Pattern Size |
| cracks Voronoi (Distance to Edge) | 5 | in noise-colour space (no metric size) | the crack warp noise |
| pebble warp noise (+-0.02 m, equal on X, Y, Z) | 20 | ~5 cm | Pattern Size |
| pebbles (4D Voronoi, Distance to Edge) | 110 | 9.1 mm cells | Aggregate Size |
| damage mask noise | 3.5 | ~0.29 m patches | Pattern Size |
| grain bump noise | 60 | ~1.7 cm | Aggregate Size (60/110) |

UV mode (Use UV = 1): UVMap x Tile Size metres on the core's flat 4D torus (arc length = metres), so the same
feature sizes repeat exactly every Tile Size (4 m by default; bakes in `tmp/materials_bake/asphalt/`).
